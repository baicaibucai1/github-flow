**采集上的两个反直觉结论：**

- 取材时**不能**先 `order by score desc limit N` 再分档 —— 高星会把名额占满，

用户贴了小红书首页和打开样式，要求"参考这个布局"。原来顶部横条 + 白卡片 + 右侧抽屉，
全部换掉：

- 搜索框居中，分类行按**语言**（不是领域）—— 数据现成，也比"推荐/热门"这种空心词有用
- 卡片去掉白底和阴影：图片本身即卡片。有容器就一格一格，没容器整片才连得起来
- 打开方式：居中浮层三段（左操作 / 中转述 / 右数据），高度 auto 只封顶

**这一轮踩的坑（都不在"布局"本身）**
1. `[hidden]` 被 `.modal{display:flex}` 盖掉 → 一打开就一块空白浮层压中间。
   顶部加 `[hidden]{display:none!important}` 兜底。
2. 图片的 opacity 淡入在无头截图里永远走不完（懒加载的图在 budget 末尾才到手），
   排查时以为"12 张图全 ok 却不显示"。**去掉淡入**，直接 `display:none → block`。
3. 透明底 PNG 会透出底下的 README 文字层（z-index 盖不住透明度）。
   改成 `.cover.is-img:not(.broken) .snip{display:none}`，加载失败再加回来。
4. 列宽用 `clientWidth` 算会含 padding，高估一档多出一列（1180 窗口挤成 5 列 165px）。
   先减 padding 得 avail 再算，1180 → 4 列 209px。
5. 超宽横幅（205/1175 张，比例 >2.2）裁切会断字（"One API ke"），改 contain。
   代价是 plannotator 那种视觉截图也变小一圈，但尺寸分辨不出"图里是字还是画面"。
6. 浮层高度写死 760px → 无图项目正文三行，底下空 480px。改成 `height:auto; max-height`。

**工具上的两个教训**
- `shot.py` 里超时执行 `taskkill /F /IM chrome.exe` **会杀掉用户正在用的浏览器**。
  已改成 `subprocess.Popen` 自己管 pid，超时只 kill 自己那一个。
- `--host-resolver-rules` 对走系统代理的 Chrome 无效，模拟图床不可达只能改数据。
- 加 `--user-data-dir=<临时目录>` 之后截图才稳定（否则参数被转交给已有实例，
  `--screenshot` 被忽略，表现就是永远不退出）。

## 2026-11-06 夜（二）：改回整卡，不再让文字悬空

照小红书做的"无容器"版（图即卡片、文字直接落灰底）被否掉了。原因很实在：
库里 3500 个项目只有 1175 条有 README 配图（三分之一），一屏下来大半是
**悬空的文字**，看着像渲染没完成。所以每张卡重新变成一整块：白底 + 12px 圆角 +
1px 浅投影，头部（图或 README 摘录）在上、正文在下，都在同一个容器里。

**这一轮的实际改动**
- `.card` 加 `background/radius/shadow/overflow:hidden`；圆角交给容器裁，
  `.cover` 不再自己设 radius。
- `animation:rise ... both` → `backwards`：`both` 会让终帧 `transform:none`
  一直生效，把 `.card:hover{transform:translateY(-2px)}` 压掉，鼠标划过不浮起来。
- 文字卡左侧那条 2px 竖线删了：贴着卡片圆角边，1x 下根本看不见，只像个瑕疵。
  内边距统一到 14px，头部文字 / 标题 / 作者头像落在同一条竖线上。
- `is-doc` 改回垂直居中：一句话的卡靠上排会在底下空出半截色带。
- 超宽横幅（`is-wide`）底色改中性 `#f7f7f9`：原来垫项目色相，蓝色横幅配粉色底，
  两块颜色打架。
- **图片加载中不再把文字层藏掉**：原来 `.cover.is-img:not(.broken) .snip{display:none}`
  从 class 一加上就生效，懒加载那几百毫秒到几秒里，头部是一块空色带。
  改成 `.cover.is-img.ok`（图片 load 时由 JS 同时给 img 和 cover 加 class）才藏。
- `is-img.broken` 单独放开 `aspect-ratio:auto`：16:10 的框装不下四行摘录，底下会被裁。
- `estimate()` 里 `colW*0.75` 是 4:3 时代的残值，改成 16:10 的 `0.625`，列高才估得准。

**工具**：`build/shot.py` 加了 `x2` 参数（二倍图看细节），`preview.html` 支持
`?data=feed-broken.json` 换一份数据看降级，不用再改 feed.json 再还原。
