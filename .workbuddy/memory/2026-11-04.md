## github-flow-v2 接了真实数据（预览页不再喂假数据）

用户开代理后（端口变成 127.0.0.1:58022，git 协议这次真的通了），要求预览界面显示真实 GitHub 项目。

**做法**：给 `core` 加了 `serve.rs`，`flow serve [端口]`（默认 8791，只绑 127.0.0.1）：
- 手写最小 HTTP（TcpListener，读头→一个响应→关连接），**没有引入任何新依赖**。
- 静态文件根：`FLOW_WEB` → `./web` → exe 旁 `web`。
- 接口：`/api/ping`、`/api/feed?sort=`、`/api/detail?id=`、`/api/repos?ids=`、
  `/api/languages`（带条数，前端取前 12）、`/api/stats`、`/api/readme|files|issues?id=`、`POST /api/refresh`。
- 卡片字段全部由核心同一套纯函数算：`rank::metrics` + `rank::score`（slope/quality/reasons 与 CLI 一致）。
- 启动后台补货：补算 score=NULL → 库超 6h 才回采 1 天 → 曲线不足 40 条时 `measure_top`。
  `REFRESHING: AtomicBool` 防并发。
- `net.rs` 加 `get_text`（Accept: raw，读 README），`github.rs` 加 `readme_raw/contents/issues`。

**前端 api.js**：`init()` 探测 `/api/ping`，通就 local 真实库，否则 mock。两种源共用同一套过滤/混排逻辑。
收藏/隐藏按数据源分 key（`gf-saved:mock` / `gf-saved:local`）——否则演示 id 会串到真库，出现「收藏 4 但页面空」。
统计页 14 天曲线：没有曝光埋点时显示说明文字，不画空图。

**踩过的坑**：
- 封面 `slope=0`（一天的仓库核心故意不外推）不能显示「+0 star/周」→ 改成显示累计 star。
- 真实数据语言有 60 多种，chips 会占五行 → 按条数取前 12。
- `?open=<id>` 要传**真实仓库 id**（GitHub id 十位数），演示 id 只在 mock 模式有意义。

**数据现状**：库 11,480 条（回采 14 天，2026-10-21 ~ 11-03），实测曲线 90 条。
通道：热度 10,631 / 探索 849 / 画像 0 / 相似 0（后两条通道还没数据源）。

**已知问题（未改，等用户拍板）**：
- 榜首有同一描述的克隆仓系列（如多个「VERY experimental Nintendo Switch 2 emulator」，
  不同 owner），fork 比例也被一起刷高，`quality()` 判不出来。数据/算法此前被用户冻结，没有擅自动。
- 详情 README 是原文 `<pre>` 展示，没接 markdown 渲染。

**启动方式**：`cd C:\AI_Project_2\github-flow-v2 && ./target/release/flow.exe serve 8791`
（要求 shell 里有 http_proxy/https_proxy，ureq 读环境变量走代理）。
