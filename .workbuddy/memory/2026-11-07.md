## web 预览「无法工作」—— 修成单文件，不再依赖端口

用户报「你拉起的 web 端无法工作」。查下来：

- **8000 端口上那个监听是 C-Lodop 打印服务**，不是本项目的。`curl /app.js` 返回 200 但内容是 C-Lodop 的页面（8291 字节），一眼看不出来。
- 之前我起的 `python -m http.server` 早就没了（中途还被用户取消过一次），所以给出的地址必然打不开。
  **教训：把 localhost 地址当交付物，等于把交付物绑在一个会死的进程上。**

### 做法：`build/mkpreview.py` 打包单文件

`python build/mkpreview.py` → `build/preview.html`（689KB），把 style.css / api.js / app.js / feed.json 全内联进去。

三个必须踩对的点：

1. **`file://` 下 Chrome 禁止加载 `type="module"`**，所以不能直接引 `../web/app.js`（它第 1 行是 import）。
   处理：把 `import * as api from "./api.js";` 换成 `const api = window.__FLOW_API__;`，
   再把 api.js 的 `export ` 前缀去掉、末尾挂 `window.__FLOW_API__ = {...}`。
2. **替身必须在 api.js 之前**。api.js 是 `const invoke = window.__TAURI__?.core?.invoke`——
   加载那一刻就抓进闭包了。替身放后面 → invoke 是 undefined → 界面报「必须从 Flow 应用里打开」。
   第一次就是这么挂的，表现为 `cols=0` + fatal 可见。
3. f-string 里写替身对象时括号层数：`window.__TAURI__ = { core: { invoke: async () => {...} } };`
   要写 `}} }} }};`（三个），我写成两个 → `} };` 语法错误 → 整页白。
   **排查手法：`re.findall(r'<script[^>]*>(.*?)</script>')` 拆块 + `node --check`，一次定位。**

数据用 `<script id="feed-data" type="application/json">` 内联，`<` `>` `&` 转成 `\u003c` 形式，
否则 JSON 里出现 `</script` 会提前闭合标签。

### 顺手修的两个「点了没反应」

预览原本 `toggle_save` / `open_url` 都 `return null`，点了看着像坏了：

- `toggle_save` → 在内存 `d.saved` 里增删（预览不落盘，刷新就没了，够用）
- `open_url` → `window.open(url, "_blank", "noopener")`

## 详情页：介绍 + README 全文 + 右侧文件树

需求「点击卡面后显示介绍，随后是 readme，右侧显示文件树」。

### 数据从哪来

本地库里只有 `readme_head`（首屏摘要），README 全文和目录都要现拉 GitHub。
在 `core/src/source.rs` 加 `Source::repo_extra(full_name)`，复用已有的 ureq/token/限流提示：

- `GET /repos/{full}` 拿 `default_branch`
- `GET /repos/{full}/readme` 带 `Accept: application/vnd.github.raw` —— **直接返回 markdown 原文，
  省一次 base64 解码**（这个仓库的 README 有 346KB）
- `GET /repos/{full}/git/trees/{branch}?recursive=1` 拿扁平 path 列表

README 或目录拉不到**不算失败**，返回空，界面自己显示「没有」；只有仓库不存在才报错。
`app/src/main.rs` 加同步命令 `repo_extra`（Tauri 会丢线程池，ureq 是阻塞式，塞 async 反而要绕）。
预览替身里直连 api.github.com（它带 CORS 头），未认证 60 次/小时。

### 自写 markdown 渲染器（`web/app.js` 的 `md()` / `inlineMd()`）

没有引三方库。安全上只有一条铁律：**先把整行 HTML 转义，再按 markdown 结构还原标签**。
顺序反了，README 里藏个 `<script>` 就能在应用里执行。
覆盖标题/代码围栏/列表/引用/表格/分隔线/行内代码/粗斜体/删除线/链接/图片。
`safeUrl()` 只放行 http/https 和仓库内相对路径，`javascript:` `data:` 一律退回纯文本。

文件树用扁平 path 按 `/` 数量缩进（`style="--d:N"`），默认只列 90 条。

### ★ 两个坑，都花了很久

**1. `chrome --dump-dom` 会把 `<script>` 里的源码一起序列化出来。**
我 grep `class="mfail"` 看到「这个仓库没有 README」，以为渲染失败了，
加了两次诊断去查 fetch、查调用链——其实那行是 **app.js 里的字符串字面量**。
正确做法：`re.sub(r'<script[^>]*>.*?</script>','',s,flags=re.S)` 去掉脚本再统计。
**诊断脚本返回正常值时，要怀疑的是诊断方法本身。**

**2. flex column 容器里，内容超出高度会把子块压扁。**
`.mcenter{display:flex;flex-direction:column;overflow-y:auto}`，内容比浮层高时，
flex 默认 `flex-shrink:1` → 封面图 `.mfig` 被压成 **高度 0**，而 `overflow:hidden`
把里面 270px 高的 img 整块裁掉，视觉上就是「没有封面图」。
修：`.mcenter>*{flex:0 0 auto}`，超出的交给 `overflow-y` 滚。
**判据：父容器 0 高 + 子元素有正常高度 + overflow:hidden = 被 flex 压了。**

### README 必须折叠

public-apis 的 README 渲染出来 **145471 像素高（约 190 屏）**。
默认 `.md.fold{max-height:1080px;overflow:hidden}` + 底部渐隐 +
`position:sticky;bottom:6px` 的「展开全部 README」按钮（不吸底的话按钮躺在 1080px 之下，
得先滚到底才发现有它）。

## 16:40 README 在预览里根本不显示 —— 根因是面板 CSP，不是网络

用户说「readme 是有对应内容的，显然，你需要渲染出来」。我之前一直用 `file://` 自测，
那里没有 CSP，所以一直显示正常；用户是在**面板 iframe** 里看的。

### 根因（实测，不是推测）

面板静态页的响应头：

```
Content-Security-Policy: ... connect-src 'self' http://127.0.0.1:* https://*.map.qq.com ...
```

**白名单里没有 `api.github.com`**。详情页原来在点开时 `fetch` 三个 GitHub 接口，
全部被浏览器拦掉。用面板地址加载 `?open=54346799`，实际拿到的是：

```
拉不到README：Failed to fetch
拉不到目录：Failed to fetch
```

注意 `img-src` 里有 `https:`，所以 README 里的远程图片不受影响，
**只有 connect-src 卡住 fetch**。exe 走原生 HTTP，不受这条约束，所以产品本身没坏。

### 做法：构建期抓一次，内联进 HTML

- 新增 `build/fetch_readmes.py`：800 个项目 → `/readme`（raw 媒体类型）+ `/git/trees/HEAD?recursive=1`
  - 令牌用 `GH_TOKEN=$(gh auth token)`，匿名只有 60 次/小时
  - 落 `build/readmes/{id}.md`、`build/trees/{id}.json`，可断点续跑
  - 巨型仓库（torvalds/linux、NVIDIA/cudf）递归树会超时 → 退 `git/trees/HEAD` → 再退
    `contents/`（只一层、响应极小）。11 个空目录是这样补回来的
- `mkpreview.py` 的 `inline_extra()`：把 README + 精简后的目录塞进 payload 的 `extra` 字段
  - 目录先 `prune_tree()`：git 树是字母序，前 90 条常常全是 `.github/` 里的点文件；
    改成「顶层全部 + 每个顶层目录 4 个直接子项」，看起来才像树
  - `[路径, 是否目录]` 数组比 `{path,type}` 省一半字节
- 替身 `repo_extra` 改成查表，不再 fetch

### 顺带修掉的一个旧 bug

`treeHTML()` 原来用 `list.length` 报「还有 N 个文件未显示」，但列表本身有 400 条上限，
数字是错的。改成 `treeHTML(entries, total)`，`total` 由后端给（Rust `RepoExtra.total`）。

### 体积

README 原始 13.5MB（gzip 只压 3.2 倍，README 里大量 base64 徽章），
covers 5.3MB → 成品 **19.8MB 单文件**。实测加载 3.4s（含 Chrome 冷启动），
19MB 这版在面板里跑得动，所以没有引入 DecompressionStream（多一个兼容性风险不值得）。

## 17:05 检讨：不该把 README 烤进预览（用户质疑「为什么总想把内容存在本地」）

用户说得对。复盘一下：本地化只发生在**预览单文件**，产品（exe）从来是点开现拉的。
我把「预览环境被 CSP 限制」这个临时困难，用「把 14MB 内容烤进 HTML」这个
永久代价去解决了，方向错了。

### 正确做法：本机代理 + 三层降级

面板 CSP 的 connect-src 里有 `http://127.0.0.1:*`（只是没有 api.github.com），
所以起一个本机小代理就行：

- 新增 `build/serve.py`：静态文件 + `/api/repo?full=owner/repo`
  - 借 `gh auth token`（匿名 60 次/小时不够用）
  - 180 秒内存缓存；CORS `*`（页面可能来自面板另一个端口）
  - 三个 GitHub 请求：meta（拿默认分支）→ readme(raw) → trees?recursive=1
- 预览的 `repo_extra` 改成三层：
  1. 本机代理（面板里唯一能走通的实时路径，有令牌有缓存）
  2. 直连 api.github.com（`file://` 双击打开时没有 CSP，**不需要任何服务**）
  3. 内联快照（只剩兜底作用，`--no-extra` 可完全关掉）

### 两个新开关

```
mkpreview.py --no-extra    不内联 README 快照
mkpreview.py --no-covers   不内联封面图
```

| 文件 | 大小 | 说明 |
|---|---|---|
| preview-live.html | 5.3MB | README 实时，封面内联（默认交付） |
| preview-raw.html | 706KB | 全部实时，图片慢（45s 还有 1 张没下来） |
| preview-offline.html | 19.8MB | 全快照，断网可用 |

### 实测

```
面板 CSP + 代理  ：README 123 段 / 54 表 / 30 行树，失败 0
断开代理 + file://：直连 GitHub 同样 123 段 / 54 表（7.5s）
代理缓存命中     ：6ms（首次真实拉取 6.4s，public-apis 346KB）
```

**教训**：遇到环境限制，先找「把请求转出去」的路，而不是「把数据搬进来」。
后者每次都多一个需要重新生成的产物。
